Fix migration cascade-path error; wire Contact page to the database

- AppDbContext: ExamResult had cascade paths to both Student and Exam,
  which both trace back to ClassRoom - two cascade paths converging on
  the same table, which SQL Server refuses to create
  ("Introducing FOREIGN KEY constraint ... may cause cycles or
  multiple cascade paths"). Set ExamResult -> Exam to Restrict to
  break the cycle; regenerated the InitialCreate migration and applied
  it to a real SQL Server instance (installed and confirmed working
  this session).
- appsettings.Development.json: corrected the connection string to
  match how SQL Server actually registered on this machine (default
  instance MSSQLSERVER, not a named SQLEXPRESS instance).
- Pages/Contact.cshtml.cs: now injects AppDbContext and loads the
  School row instead of returning hardcoded values. Also fixes a
  real pre-existing bug: Contact.cshtml's markup never actually used
  ContactModel's properties at all - the page just had the same
  placeholder text written directly into the HTML, so the model's
  properties existed but were dead code. The view now binds to
  @Model.SchoolName / AboutUs / Address / Dial / Mobile / Fax / Email
  for real, plus renders a real school logo image when SchoolLogo is
  set instead of always showing the placeholder box.
- Verified end-to-end by updating the School row directly in SQL
  Server (bypassing the app entirely) and confirming /Contact picked
  up the change with zero code or file changes - proving the "point
  this app at a different school's database and it serves that
  school's data" premise actually holds.
